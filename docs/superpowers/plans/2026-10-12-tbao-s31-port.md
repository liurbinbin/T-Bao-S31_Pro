# T-Bao S31 Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task with verification checkpoints.

**Goal:** Make `esp32-s31-vocat-main` build and run the existing Xiaozhi application on T-Bao S31 with OV2640/OV3660-compatible camera capture.

**Architecture:** Add an isolated `tbao_s31_board` Board Manager definition and local camera/LCD component copies. Replace the SC101IOT V4L2 pipeline with a PARLIO JPEG pipeline while retaining the existing application-level JPEG interfaces; decode JPEG to RGB565 only for LCD preview and vision analysis.

**Tech Stack:** ESP-IDF 6.1, ESP32-S31, Board Manager 0.5.10, `haqqscripter/esp_cam_io_parl`, `esp_lcd_st7796`, `lambage/esp_lcd_touch_ft6336u`, `sheldonix/esp_io_expander_xl9555`, LVGL, hardware JPEG decoder.

**Spec:** `docs/superpowers/specs/2026-10-12-tbao-s31-port-design.md`

## Global Constraints

- Use IDF 6.1 for Board Manager generation, reconfigure, and build.
- Do not modify or overwrite source-project user changes.
- Keep `esp_vocat_s31_board` available and add `tbao_s31_board` as a separate board.
- Use the exact camera data mapping GPIO46..GPIO53 for PARLIO indexes 0..7.
- Do not claim GPIO56 VSYNC as active in the camera component because the local component does not implement VSYNC.
- Do not use SC101IOT, `/dev/video2`, `/dev/video10`, V4L2, or `esp_video_device.h` in the migrated application.
- Treat OV2640/OV3660 DVDD profiles as distinct and fail on an incompatible selected profile.
- Use `MM` for the T-Bao ES7210 two-microphone layout.
